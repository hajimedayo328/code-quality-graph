⚠ AI判定を100%信じないでください
LLMは 人間レビューを支援する補助役 です。優先度付けの参考にしつつ、最終判断は必ず人間が下してください。 軽量モデルでは特に、誤判定・見逃し・繰り返し生成が起きます（その場合は ⚠カード で補完表示します）。
検出精度を上げるための情報源（多いほど精度UP）： ① doctest（自動抽出）→ ② Inspector の意図メモ（任意で書ける）→ ③ Phase C のテスト失敗結果（強い証拠）→ ④ 呼び出し元/先のシグネチャ（クロス関数文脈）→ ⑤ グラフ異常スコア（他関数と異質か）。
コードは外部送信されません（モデル本体だけCDN取得）。

📋 プロジェクト全体の目的（全LLMタスクに必ず投入されます）
50〜200字で具体的に書くと精度が大きく上がります。「何をする/誰向け/主要機能/前提」を含める。
NG例:「教えて」「便利ツール」 → LLMが判定基準を持てず無意味な出力に。
🌐 プロジェクト整合性判定（最重要）
上の「📋 プロジェクト全体の目的」と各関数の役割を照合。「目的に貢献してる関数」「無関係な関数」「足りない処理」を一覧で出す。関数単体じゃなく森を見る唯一のタスク。
🔍 意味的バグ検出
コンパイルは通るが「論理が逆」「境界値ミス」「意図と違う動き」を発見。静的解析で拾えない論理エラーを補完。
📝 関数を1行で説明

ほぼ同じコードが複数箇所にある。共通化でメンテが楽になる
バーの長さ = コード量。長すぎるファイルは分割を検討

⚠️ 動作要件：WebGPU 対応ブラウザが必須（Chrome 113+ / Edge 113+ 推奨、Firefox/Safariは限定的）。
